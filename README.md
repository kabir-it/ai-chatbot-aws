# AI Chatbot on AWS

A generative-AI chatbot that runs as a web server on **AWS EC2**. Every answer is written by a Claude model on **AWS Bedrock**. The model can also call small tools to get live information: web search, weather and the current date and time.

> Project by **Md Humayun Kabir (K@BIR)**, Jensen Education, Kombo OCT25 · *askforhelp by K@BIR*
>
> Live site (while the AWS instance is running): **https://askforhelp.duckdns.org**

The full project documentation (research, implementation, problems and solutions, conclusion) is in [`docs/Project_Documentation.pdf`](docs/Project_Documentation.pdf).

## Features

- Chat interface in the browser (light and dark theme, works on mobile)
- Answers generated by a model on AWS Bedrock (Converse API)
- Tool use for current information: `get_current_time`, `get_weather` (Open-Meteo), `web_search` (DuckDuckGo)
- No API keys in the code: the EC2 instance uses an **IAM role** to call Bedrock
- Production-style setup: nginx → gunicorn → Flask, started by systemd
- Free domain name (DuckDNS) with a trusted HTTPS certificate (Let's Encrypt)

## Architecture

```
Browser ──HTTPS──▶ EC2 (nginx :80/:443 ──▶ gunicorn/Flask :8000) ──IAM role──▶ AWS Bedrock (Claude)
                                          └── tools: time, weather, web search
```

## Configuration

Settings are environment variables (all have defaults):

| Variable | Default | Meaning |
|---|---|---|
| `AWS_REGION` | `eu-north-1` | Region for Bedrock |
| `BEDROCK_MODEL_ID` | `eu.anthropic.claude-haiku-4-5-20251001-v1:0` | Model or inference profile ID (copy the exact ID from the Bedrock console) |
| `TIMEZONE` | `Europe/Stockholm` | Time zone for the date and time tool |
| `SYSTEM_PROMPT` | helpful assistant | Instructions given to the model |

## Run locally

1. Install the AWS CLI and run `aws configure` with a user that may call Bedrock.
2. In the AWS console (region eu-north-1) make sure a Claude model is available to your account.
3. Start the app:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export AWS_REGION=eu-north-1
export BEDROCK_MODEL_ID=<model-or-inference-profile-id>
python app.py
```

Open http://localhost:8000.

## Deploy on AWS (EC2)

1. **IAM role:** create a role for EC2 (for example `chatbot-ec2-role`) and attach the policy in `deploy/bedrock-policy.json`.
2. **EC2 instance:** Ubuntu, region eu-north-1, role attached, security group with SSH (22) and HTTP (80). Give it a public IP (Elastic IP).
3. **Copy the files** to `~/chatbot` on the server and install:

```bash
sudo apt update && sudo apt install -y python3-venv nginx
cd ~/chatbot
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

4. **Service:** copy `deploy/chatbot.service` to `/etc/systemd/system/`, set `BEDROCK_MODEL_ID`, then:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now chatbot
```

5. **nginx:** copy `deploy/nginx-chatbot.conf` to `/etc/nginx/sites-available/chatbot`, then:

```bash
sudo rm -f /etc/nginx/sites-enabled/default
sudo ln -s /etc/nginx/sites-available/chatbot /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl restart nginx
```

6. Open `http://<public-ip>` in a browser.

### Domain name and HTTPS

A certificate can only be issued for a domain name, not a bare IP. This project uses the free DuckDNS domain `askforhelp.duckdns.org`:

1. At [duckdns.org](https://www.duckdns.org) create a sub-domain and set its IP to the Elastic IP of the server. Check it on the server with `getent hosts askforhelp.duckdns.org`.
2. Open **port 443 (HTTPS)** in the security group (keep port 80 open).
3. In `deploy/nginx-chatbot.conf` set `server_name askforhelp.duckdns.org;`, copy the file to `/etc/nginx/sites-available/chatbot` and reload nginx.
4. Request a free Let's Encrypt certificate (certbot also sets up automatic renewal):

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d askforhelp.duckdns.org
```

Then open `https://askforhelp.duckdns.org`.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| "The AI service is unavailable right now." | Wrong model ID, model not enabled for the account, or IAM role missing. Check `sudo journalctl -u chatbot -n 50`. |
| Page does not load | Port 80 or 443 missing in the security group, or nginx not running. |
| Certbot fails | The domain does not point to the Elastic IP yet, or port 80 is blocked. |
| 502 Bad Gateway from nginx | The app is not running: `sudo systemctl restart chatbot`. |
| Cannot connect with EC2 Instance Connect | The instance has no public IP; attach an Elastic IP. |

## Cost and security notes

- The EC2 instance, the Elastic IP and Bedrock calls cost money. After the project is graded, **terminate the instance and release the Elastic IP**.
- The site is public and has no login. Add authentication or rate limiting before real use.
- Never commit `.pem` key files or access keys (they are in `.gitignore`).
